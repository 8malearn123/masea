## 1. نتيجة الفحص

### 1.1 السبب الحقيقي لوجود «مسارين»

المعالج **مربوط فعلاً** بقالب التأجير الأصلي (`ContractWizard.tsx` سطر 269–334): عند اختيار تأجير شهري أو يومي يستخدم `approvedTemplateFor()` ويعرض في المعاينة العقد كاملاً بمحرك `rentalContractHtml` ويحفظ `doc_fields` ويثبّت نسخة القالب وبصمته على العقد.

**لكن** القالب نفسه حالته «بانتظار الاعتماد» (بذرة 0087 والوضع التجريبي `DEMO_TEMPLATES.status = 'pending_review'`)، فيرجع المعالج **بصمت** إلى القوالب القديمة المختصرة (0046: «تأجير شهري — شامل/مختصر»، «تأجير يومي — قياسي») التي تخالف الأصل (مثل «يُجدَّد تلقائياً»، «الاستبدال خلال 3 أيام عمل»). أما القالب الأصلي فلا يظهر إلا في صفحته المستقلة. هذا ما يجعل التجربة تبدو كمسارين.

## 2. تصميم الحل

```
                      ┌──────────────── contract_templates (template_code = rental_labor_services, v1, مقفل) ──┐
 «عقد جديد» ─► المعالج │  شهري / يومي / بالساعة ─► نفس القالب ─► doc_fields + template_version + sha256 ─┐      │
                      │  استقدام / نقل كفالة ─► مسار مساند (بلا نص داخلي)                              │      │
                      └────────────────────────────────────────────────────────────────────────────────┘      │
                                                                                                             ▼
 قائمة العقود ─► صفحة التفاصيل (تبويبات) ─► «المستندات» ─► contractDocumentHtml(contract) ◄── محرك واحد
                                                         └ معاينة مدمجة = طباعة = تنزيل PDF
```

### 2.1 مصدر واحد لنص عقود التأجير

- `approvedTemplateFor()` يبحث بـ `template_code` لا بالخدمة فقط ← نفس النسخة المعتمدة للشهري واليومي **وبالساعة** (بدون نسخ النص؛ القالب واحد).
- **لا رجوع صامت** للقوالب القديمة في التأجير: إن لم يُعتمد القالب تتوقف خطوة المعاينة برسالة ورابط «مراجعة القالب واعتماده» (لمن يملك الصلاحية). القوالب القديمة تبقى في القاعدة لعقودها السابقة فقط وتُعلَّم «موقوفة للعقود الجديدة» (`is_active = false`) — لا حذف.
- لا حقل في المعالج يعدّل نصاً قانونياً؛ المتغيّر فقط الحقول `{{…}}`.

### 2.2 المعالج

- الخطوات الخمس كما في الطلب (الخدمة ← التفاصيل ← العميل ← التسعير ← المعاينة) مع شريط تقدّم؛ العاملة داخل «التفاصيل» من المتاحات فعلاً (وبالساعة: من غير المحجوزات في الوقت المختار).
- **التأجير بالساعة من المعالج**: حقول التاريخ ووقت الوصول والانصراف، والحفظ عبر `book_hourly` القائمة (حجز + طلب تشغيل + عقد) ← تُسدّ ثغرة العقد بلا حجز.
- التسعير بنفس `calc_price`/`usePrice` دون أي تعديل في المعادلات؛ يُعرض المدفوع والمتبقي.
- **حفظ المسودة تلقائياً** محلياً (لكل مستخدم) ومنع فقدان البيانات عند الخروج، مع «استئناف المسودة».
- المعاينة = المستند الكامل بنفس المحرك (بيانات الشركة والعميل والعاملة والمدة والقيمة والبنود والتوقيعات) + زر معاينة PDF.

### 2.3 محرك مستند واحد

- `contractDocumentHtml(contract)`: عقد تأجير (له `template_version`) ← `rentalContractHtml` بالقالب المثبّت **وقت توقيعه** و`doc_fields` المجمّدة؛ غير ذلك ← `buildContractHtml` ببنوده المحفوظة. تستعمله المعاينة والطباعة والتنزيل في المعالج والتفاصيل.
- العقد القديم يعرض «غير متوفر» لأي حقل ناقص، ولا يُستبدل نصه بنسخة أحدث أبداً.

### 2.4 صفحة التفاصيل (تعديل الصفحة القائمة لا صفحة جديدة)

- **رأس**: رقم العقد، الخدمة، العميل، الحالة، تاريخ الإنشاء، البداية والنهاية + أزرار حسب النوع والحالة والصلاحية (عرض، PDF، تعديل المسودة، إرسال للاعتماد، تسجيل دفعة، تجديد، استبدال، إرجاع، إلغاء وتسوية).
- **تبويبات**: نظرة عامة · الأطراف · البنود · المالية · العمليات · المستندات · سجل النشاط — تُبنى من الأقسام الموجودة اليوم (`ContractOpsPanel`، `TrialPanel`، `RecruitmentJourney`، `MusanedPanel`، `TermEditor`، التوقيعات، السجل) دون إعادة كتابتها.
- **تسجيل دفعة**: نافذة تُدرج في `payments` (صلاحية `payments.create`) ← يُحدَّث المدفوع ويُرحَّل القيد تلقائياً (0089).
- لا تُعرض حقول لا تخص الخدمة (مثلاً لا عاملة في نقل الكفالة قبل الربط، لا مدة في الساعة بل التاريخ والوقت).

### 2.5 القائمة

- تبقى الصفحة نفسها مع إضافة فلتر **الفترة** (من/إلى) و**العميل**، وتبويب أو خيار «تجربة نقل الخدمات»، وتبقى تنبيهات الانتهاء والتجديد كما هي.

### 2.6 إزالة البريد المؤسسي (غير مدمّرة)

1. الواجهة: حذف `features/it-admin`، المسار، عنصر القائمة، الأيقونة، و`it_admin` من مرآة الصلاحيات.
2. القاعدة: migration جديدة **تعطّل الوصول فقط** (حذف صفوف `role_permissions` و`permissions` لـ `it_admin` ← RLS يمنع القراءة، وسحب تنفيذ الدوال من `authenticated`). **الجداول وبياناتها تبقى** حتى موافقتكم على حذف نهائي بتقرير منفصل.
3. تحديث `role_permissions.json` وحذف `99t` وتعليم المرحلة 6 «أُلغيت» في الخطة والتقرير.
4. لا مساس بـ `outbound_messages` ولا إشعارات العقود.

## 5. الاختبارات (بعد التنفيذ)

السيناريوهات الستة عشر في الطلب، كلٌّ باختبار آلي:

- Vitest للمعالج (شهري/يومي/ساعة، التعبئة التلقائية، السعر والضريبة، المسودة)، والمحرك الموحّد (تطابق نص المعاينة والمحفوظ والطباعة **حرفياً** ببصمة القالب)، وصفحة التفاصيل (عقد جديد وعقد قديم «غير متوفر»)، والقائمة والتنبيهات، وغياب البريد المؤسسي من القائمة والمسارات.
- SQL: العقد يثبّت نسخة القالب وبصمته، توقيعه لا يتغيّر، الساعة تنشئ الحجز، `it_admin` بلا وصول، الإشعارات (`outbound_messages`) تعمل.
- مقارنة قبل/بعد: كل اختبارات الوحدات الأخرى (117 ملف Vitest، 34 ملف SQL) تبقى ناجحة.
