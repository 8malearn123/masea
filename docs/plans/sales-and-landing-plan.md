## 1) اختبار وحدة «المبيعات والعقود» بالكامل وإصلاح الأخطاء ☐

النطاق: العملاء المحتملون (/leads)، العقود (/contracts)، المبيعات (/sales)، التسعير (/pricing).

- [x] مسح الصلاحيات (9 أدوار × 6 صفحات) — مطابق، بلا أخطاء.
- [ ] العملاء المحتملون: النموذج، المراحل، البحث، الملف، عروض السعر، التحويل لعقد.
- [ ] العقود: القائمة، المعالج، التفاصيل وانتقالات الحالة، التجديد، تنبيهات الانتهاء.
- [ ] المبيعات: اللوحة والمؤشرات والتصفية والتفاصيل.
- [ ] التسعير: الحاسبة، قائمة الأسعار، عروض الأسعار، الخصومات والكوبونات، السجل، الإعدادات.
- [ ] إصلاح الأخطاء + اختبارات + تجربة متصفح + تقرير بالعربي.

ملاحظات أولية (العملاء المحتملون):

- النموذج: الاسم الفارغ لا يعطي رسالة، الجوال بلا تحقق، القيمة غير الصالحة تصير 0، الحقول غير مرتبطة بعناوينها.
- crm.api: createLead يبتلع خطأ الخادم ويحفظ في الذاكرة؛ «هدفي الشهري» و«التجديدات» أرقام ثابتة
  حتى مع خادم حقيقي؛ الأنشطة لا تُقرأ من القاعدة؛ القائمة ترجع لبيانات تجريبية عند الفراغ.

## 2) صفحة الهبوط لماسية الشرق (بعد إنهاء 1) ☐

موجز المستخدم (Master Prompt): صفحة هبوط فاخرة عربية RTL بمستوى عالمي، مبنية داخل المشروع الحالي
دون تغيير وظائفه. الأقسام: Hero (عنوان، وصف، «اطلب خدمتك الآن» و«اكتشف خدماتنا»، صورة)، الثقة
(أرقام حقيقية فقط)، الخدمات (استقدام، تأجير شهري، تأجير يومي، تأجير بالساعة 4–12 ساعة)، لماذا نحن،
كيف تعمل، تجربة مميزة غير متماثلة، أسئلة شائعة Accordion (بلا اختلاق سياسات/أسعار)، CTA ختامي،
تذييل. التحويل: نموذج طلب يُرسل فعليًا إلى نظام العملاء المحتملين الموجود + واتساب إن وُجد الرقم
الرسمي، حالات الإرسال/النجاح/الفشل. التصميم: هوية المشروع (ألوان، Alexandria، الشعار)، حركة
ناعمة، تجاوب حقيقي للجوال، SEO (meta، OG، بيانات منظمة متى توفرت)، أداء، بلا أخطاء Console.
ممنوع: اختلاق أرقام/شهادات/سياسات، صور مكسورة أو بلا حقوق، API وهمية.
المراحل: تحليل → توجه إبداعي → تطوير → ربط → اختبار وتحسين (أحجام شاشات متعددة).

- [ ] التنفيذ والربط والاختبار والتقرير.
