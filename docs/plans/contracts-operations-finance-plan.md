## 3. تصميم التغييرات

### 3.1 قاعدة البيانات (migrations جديدة، غير مدمّرة)

| الجدول/الدالة                                     | التغيير                                                                                                                                                                                                                          |
| ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pricing_rules`                                   | أعمدة `package_name` و`duration_count` (اختيارية) ← **الباقة = قاعدة تسعير مسمّاة** في نفس الجدول، لا جدول أسعار ثانٍ. `calc_price` لا يتغيّر                                                                                    |
| `bank_accounts`                                   | `holder_name`, `account_no`, `currency` (افتراضي SAR), `branch_id`, تحقق الآيبان `^SA[0-9]{22}$`؛ قراءة الآيبان كاملاً لمن يملك `payments.view`/`accounting`                                                                     |
| `payments`                                        | `bank_account_id`, `transaction_no`, `status` (`received`/`pending_clearance`/`bounced`)؛ `post_payment_received` يرحّل على **حساب البنك المختار** إن وُجد                                                                       |
| `contract_installments` (جديد)                    | جدول الاستحقاقات: العقد، المبلغ، تاريخ الاستحقاق، المدفوع، الحالة (مستحق/مدفوع جزئياً/مدفوع/متأخر) — تُغطّى من الدفعات تلقائياً بالأقدم أولاً                                                                                    |
| `invoices`                                        | `issue_contract_invoice(contract)`: فاتورة للعقد عند **الحدث الضريبي** (التوقيع/بداية التوريد) بمبلغ العقد قبل الضريبة والخصم والضريبة؛ لا قيد إيراد مكرر (الإيراد مُرحّل عند التوقيع — الفاتورة توثيق ضريبي)؛ QR المرحلة الأولى |
| `sales_credit_notes` / `sales_debit_notes` (جديد) | التسوية تُنشئ إشعاراً دائناً **مربوطاً بفاتورة العقد**؛ الرسوم الإضافية إشعار مدين                                                                                                                                               |
| `driver_tasks` (جديد)                             | مهمة توصيل/استلام: العقد، العاملة، العميل، السائق، النافذة الزمنية، العنوان، الحالة (مسندة/في الطريق/منفّذة/ملغاة)، وقت التنفيذ الفعلي؛ **قيد استبعاد** يمنع مهمتين متداخلتين للسائق نفسه؛ تُنشأ من التسليم والإرجاع والاستبدال  |
| `worker_history` (view)                           | عقود العاملة (السابقة/الحالية) + استبدالاتها + إرجاعاتها — من الجداول القائمة                                                                                                                                                    |
| `worker_next_free_date()`                         | تاريخ توفر العاملة المحسوب من عقودها الحيّة                                                                                                                                                                                      |

### 3.2 الواجهة

- **المعالج**: لوحة اختيار العاملة بجدول قابل للبحث والتصفية (جنسية/مهنة/فرع)، تعرض المتاحة وغير المتاحة (مع السبب وتاريخ التوفر) وتمنع اختيار المتعارضة؛ الرقم الداخلي والإقامة/الجواز؛ تاريخ التسليم المتوقع؛ اختيار **الباقة** في التسعير؛ قسم **المدفوعات** (جدول الاستحقاقات + الدفعة الأولى وطريقتها والحساب المستلم).
- **التفاصيل**: تبويبات حسب النوع — نظرة عامة · بيانات العاملة (+ سجلها) · بنود العقد · المالية (الدفعات والاستحقاقات والحسابات **والفواتير الضريبية** وإشعاراتها) · التوصيل والاستلام (السائق والمهام وحالتها) · الاستبدالات والإرجاع · المستندات · سجل النشاط.
- **قائمة العقود**: 7 مؤشرات المطلوبة، أعمدة العاملة والمدفوع والمتبقي، تصدير CSV حسب الصلاحية، أزرار: عقد جديد · إدارة قوالب العقود · متابعة العقود · عقود التجربة.
- **حسابات الشركة**: توسيع شاشة البنوك القائمة في المحاسبة (لا شاشة ثانية).
- **السائقون**: جدول مهام السائق وحالته داخل وحدة الطلبات والسائقين القائمة، وتظهر المهام في تطبيق السائق.

## 5. قرارات مطلوبة

| #   | القرار                          | توصيتي                                                                                                                                                               |
| --- | ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **الباقة**                      | قاعدة تسعير مسمّاة بمدة داخل `pricing_rules` (مصدر سعر واحد)، لا جدول باقات منفصل                                                                                    |
| 2   | **الحدث الضريبي للفاتورة**      | فاتورة واحدة بقيمة العقد عند توقيعه (يتسق مع ترحيل الإيراد الحالي عند التوقيع). البديل: فاتورة لكل دفعة/شهر — يتطلب تغيير الترحيل                                    |
| 3   | **الفوترة الإلكترونية (ZATCA)** | المرحلة الأولى (QR وبيانات الفاتورة) داخل النظام؛ **المرحلة الثانية (الربط والختم مع «فاتورة») تحتاج شهادة واشتراك من الشركة** — خارج هذا التنفيذ ويُجهّز لها الهيكل |
| 4   | **مهام السائق**                 | جدول `driver_tasks` جديد يظهر في تطبيق السائق، بدل استخدام طلبات العملاء (`service_requests`) كمهام توصيل                                                            |
| 5   | **حسابات بنكية حقيقية**         | الموجود في البذرة آيبانات تجريبية؛ أُبقيها للوضع التجريبي فقط ولا أضيف حسابات — تُدخلون حساباتكم الفعلية من الشاشة                                                   |
| 6   | **النشر**                       | كما سابقاً: أدمج كل مرحلة بعد نجاح فحوصاتها (تُنشر تلقائياً)، أو أتوقف قبل الدمج للمراجعة                                                                            |

## 6. المخاطر

- **الفواتير**: إصدار فاتورة لعقود موقّعة سابقاً يجب أن يكون **يدوياً بقرار المحاسب** (لا إصدار جماعي بأثر رجعي).
- **ترحيل الدفعات على حساب مختار**: الدفعات السابقة تبقى على قيودها (لا إعادة ترحيل).
- **مهام السائق**: تطبيق السائق الحالي يقرأ الطلبات؛ إضافة المهام تتطلب تعديله بحذر دون كسر مسار الطلبات.
- **البيانات الحساسة**: الآيبان ورقم الحساب محميان بالصلاحيات؛ لا تُعرض في واجهات العملاء.
